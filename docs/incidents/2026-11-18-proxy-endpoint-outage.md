# MagicNet 代理出口超时诊断与恢复记录

日期：2026-11-18（UTC+8）

## 当前结果

手机实际联网路径已经恢复。通过 ADB 的非 root 身份（UID 2000）运行系统 curl，使用系统 DNS 和 MagicNet 的透明代理路径，百度、Google、Cloudflare 三项 HTTPS 请求全部成功。此次处置修改并持久保存了节点选择；设备仍运行 MagicNet v1.8.9（versionCode 10617）。

## 故障点与证据

直接故障点是当时选中的代理端点从该设备不可达。代理核心和 TUN 虚拟网卡仍然存在，但核心日志反复记录该端点的 TCP 连接超时。直连国内站点成功，同一配置中的另一个代理节点通过了两个不同站点的端到端测试。

| 检查 | 处置前结果 | 含义 |
| --- | --- | --- |
| 代理核心进程 | 存活，控制 API 和本地 DNS 端口监听 | 核心没有退出 |
| TUN 与路由 | magicnet0 存在，接管路由存在 | 流量仍进入模块 |
| root 直连百度 HTTPS | HTTP 200，0.187275 秒 | 基础蜂窝联网路径可用 |
| 原选中节点的 TCP | 3 秒内未建立连接 | 故障发生在代理出口连接阶段 |
| 原选中节点的指定出口测试 | 失败 | 此节点无法完成测试请求 |
| 备用节点访问 Google | 成功，201 毫秒 | 备用节点可用 |
| 备用节点访问 Cloudflare | 成功，205 毫秒 | 备用节点通过第二个站点验证 |
| 原普通代理请求 | HTTP 000，连接超时 | 用户流量所用路径受影响 |

上述结果定位到设备与原代理端点之间的连接路径。未进一步判定端点服务、线路或运营商路径中哪一方导致超时。

## 为什么会表现为大量应用没网

模块把应用流量送入 TUN，再由所选代理节点转发。许多域名的 DNS 查询使用经 proxy 转发的加密 DNS；代理出口失效时，域名解析和后续连接都可能超时，因此影响范围会超过单个应用。

自动恢复保留用户的节点选择。现有恢复动作依次包括规则修复、订阅刷新和核心重启；订阅刷新后会重新应用已经保存的选择。因此刷新成功后仍可能继续使用原失效节点。

连续失败还会延长复查间隔。现场连通性状态记录 12 次连续失败，退避间隔已达到 1800 秒。最后一次 refresh 的 action_status=ok 表示刷新动作执行完成；online 状态需要后续真实 HTTPS 探测更新。

## 已实施处置

通过现有 `cli api select <group> <node>` 接口，将 6 个仍选择失效节点、且允许选择已验证备用节点的组更新到备用节点：

- proxy
- ai-proxy
- ai-chatgpt
- ai-gemini
- ai-grok
- ai-claude

随后核对运行时选择和 `.config/magicnet/selector-selections.json`：残留的失效手动选择为 0，保存条目为 6，全部与健康备用节点一致。该接口同时关闭受相关组影响的旧连接。自动测速组 proxy-auto 后续也已选择健康节点。

完成 `cli state reconcile`。原选择和回滚材料已在开发机私有备份目录保存并验证，手机上的本次临时材料已清理。

## 恢复验证

以下请求来自手机上的非 root ADB shell，未显式使用 SOCKS 代理，走系统 DNS 和透明接管路径。

| 目标 | HTTP 结果 | 总耗时 |
| --- | --- | --- |
| 百度 | 200 | 0.232905 秒 |
| Google generate_204 | 204 | 0.327008 秒 |
| Cloudflare generate_204 | 204 | 0.330588 秒 |

这验证了该非 root 身份的系统 DNS、透明流量路径及所测国内外 HTTPS 访问。未逐一操作所有应用页面。

官方 `cli health` 检查得到 12 项 ok、1 项 warn。警告来自尚未到期的连通性缓存：最近记录时间为 03:11:30，计划下一次复测时间为 03:44:20。处置后的真实请求已经成功，缓存状态仍等待计划探测。没有手工将缓存中的 offline 改写为 online。

## 订阅状态补充

现场订阅处理记录为：1 个配置源且处理成功，原生解析计数 48，最终导入 2，跳过计数 46。持久过滤配置包含 6 条排除关键词；规则按节点名称进行大小写不敏感的固定子串匹配。

跳过计数还可能包括信息项、无效项和重复项，不能将 46 个全部归因为关键词过滤。本次保留现有过滤偏好，使用当前已导入的健康备用节点完成恢复。

## 后续代码改进边界

本次完成的是设备配置恢复和故障定位。以下实现问题已记录，未在本次修改或发布：

1. 人工成功切换节点后，应请求一次提前的真实连通性检查，同时保留自动恢复的冷却时间。
2. 界面应区分“核心运行”“所选出口不可达”“上次检测已过时”，展示实际检测时间。
3. 自动恢复对手动选择失效节点的处理，需要独立的、明确的切换策略；单纯重复订阅刷新会继续保留该选择。
