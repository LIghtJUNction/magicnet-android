# Requirements, implementation and verification matrix

The scope is the complete eight-package input with SHA-256 `502e160a363ffdc6e60477261ac15b74884b07f37de78af69558b0806f8e717a`. No M01–M39 scenario was removed because a later requirement emphasized subscriptions. “Implemented” below identifies actual source paths; it is not a test result. PASS applies only to the expressly described test slice. NOT_RUN identifies an unexecuted verification, never an intentionally missing implementation. These are builder self-tests; independent acceptance remains a separate step. The repaired v1.8.1 / 10609 candidate has additional P1/P2 evidence in the root VERIFICATION.md. The earlier 540-case browser matrix is retained first-candidate evidence, not a full rerun of the repair.

## Subcontract traceability

[RUNTIME_VERIFICATION.md](RUNTIME_VERIFICATION.md) maps the SUB-001–015, SUB-A01–18, C-SUB, VE-001–006 and POLICY-A01–07 slices to concrete test names and states their unexecuted cross-products. It must be read with the final combined-tree report, because owner, backup, hotspot and control integration fixes were added after the runtime agent's earlier test runs.

WebUI contracts live in `webui/model.js`, `webui/bridge.js` and `webui/app.js`; verification lives in `webui/tests/contracts.test.mjs`, `webui/tests/browser.mjs` and `webui/tests/http-integration.mjs`. The actual JSON reports identify tested sizes, language/theme combinations and real backend operations. Installer contracts are exercised by `module/installer/main_test.go` and `scripts/verify-package.py`; its report distinguishes full/offline/reuse installation and bad input rejection.

## Genuine external limitations

No Android device or emulator with the required root manager, cgroup/BPF permissions, supported vendor kernel, tethered client or multi-user applications was supplied. No real subscription credential, WARP/Tailnet account or compatible enabled-VLESS-Encryption server was supplied. The implementation therefore records unknown capability/readiness or a concrete provider failure at runtime, and this report records the corresponding tests as NOT_RUN. Host fixtures are not substituted for those observations.

The independent builder did not install an external update package, push a source repository or create a Release. Candidate-branch synchronization by the coordinator is recorded separately. The fixed core/rules/ecapture/panel/toolchain downloads are the explicitly allowed build dependencies, not evidence of an Android deployment.
