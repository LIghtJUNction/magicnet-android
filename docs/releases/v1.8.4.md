# MagicNet v1.8.4

修复 [#434](https://github.com/LIghtJUNction/MagicNet/issues/434)：未设置订阅 User-Agent 时，curl 默认标识可能被订阅服务或 CDN 以 HTTP 403 拒绝。现在默认标识遇到 403 时，同一次更新内改用 `clash.meta` 重试一次；该值不会写入配置，也不会覆盖用户自定义的 User-Agent。仍被拒绝时，日志提示在订阅设置中选择客户端 User-Agent。

订阅地址解析把 IPv4-mapped IPv6（`::ffff:a.b.c.d`）按嵌入的 IPv4 校验和钉选，避免 Rust 与 shell 双重校验不一致导致公网地址被误拒。

MCP 通用 `magicnet_file_read` 不再读取路由/屏蔽域名清单、`block.conf` 和 `proxy-chain.json`；通用 `magicnet_cli` 拒绝人类 `warp`/`node`/`route`/`block` 默认清单。具名的 `magicnet_node_list`、`magicnet_node_current`、`magicnet_block_list` 仍可显式使用。删除无调用方的 `magicnet_prepare_singbox_nodes` 包装。

本地验证见主仓库提交记录。未进行真机安装验收；#434 的修复基于用户日志中的 HTTP 403，尚需报告者在设备上确认。
